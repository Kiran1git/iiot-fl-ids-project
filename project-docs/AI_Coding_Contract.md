PART A — Global Invariants

These hold across the entire project, at every phase, with no exceptions.

A.1 Global Project Invariants

The SDS Revision 2.1 architecture is frozen. No agent may substitute a library, dataset, model family, or framework named in SDS Section 7/1/2.

No phase may begin before all of its Required Previous Phases (Part B, per-phase) have passed their Validation Gate.

No phase may create, rename, move, or delete a file outside the exact set listed for that phase in Part B.

Every numeric hyperparameter, file path, and class count is sourced from configs/config.yaml or derived at runtime (num_classes = len(class_mapping)) — never a literal in src/.

Every multi-component file path is built with os.path.join(...); string concatenation with / or \ is forbidden anywhere in src/, experiments/, dashboard/.

The single authoritative specification is the SDS plus this contract plus the Blueprint. No separate addendum, patch note, or "supplementary design decision" document may be introduced or consulted by an agent.

A.2 Data Invariants

data/raw/edge_iiotset.csv is never written, modified, or regenerated by any script, at any phase.

Native columns Attack_type and Attack_label are removed from the working DataFrame exclusively inside create_labels — no other function, in any phase, may drop either column.

label and binary_label are derived exactly once, during preprocessing. No downstream module re-derives them from raw source data.

Categorical/numeric column classification happens exclusively via infer_feature_column_types, rule "dtype_object" only. No other function independently re-classifies columns.

Any encoder, scaler, or label encoder is fit only on df.loc[train_indices]. Fitting on the full dataset (train+test) before the split is a leakage defect regardless of which phase or agent introduces it.

The train/test split is computed once (split_train_test), persisted (train_indices.pkl, test_indices.pkl), and reused everywhere. No phase re-splits the data.

Federated client shards (partition_iid) are drawn only from train_indices rows. The shared test split is never partitioned per client.

A.3 Model Invariants

Exactly one architecture exists in the project: build_cnn_gru, with the exact 7-layer sequence specified in SDS Section 14.4. No agent may add, remove, or reorder a layer.

Conv1D.padding is always "same"; GRU.return_sequences is always False. These are not configurable and must not become configurable.

num_classes is never hardcoded. It is always len(class_mapping) read from outputs/artifacts/class_mapping.json.

Adam is the only optimizer ever instantiated in build_cnn_gru. config["training"]["optimizer"] is documentation-only and must never be read as a live branch.

The same build_cnn_gru function is used to build both the centralized model and the reconstructed federated global model. No second model-building function may be introduced.

A.4 Training Invariants

Centralized training always uses EarlyStopping(monitor="val_loss", patience=3, restore_best_weights=True) and ModelCheckpoint(save_best_only=True, monitor="val_loss"), values sourced from config.

centralized_best_model.h5 (lowest val_loss) is the only model ever read by evaluation, comparison, or dashboard code. centralized_last_model.h5 exists for audit only and must never be loaded by any other script.

Training-time measurement (time.time()) wraps only the .fit() call (centralized) or only start_simulation(...) (federated) — never the surrounding script's I/O or plotting.

validation_split is applied by Keras internally to the training array; no separate validation file is ever produced or read.

A.5 Federated Learning Invariants

The Flower API in use is the pinned flwr==1.8.0 client-function/strategy-based start_simulation API. The newer ClientApp/ServerApp/run_simulation API must never be introduced, at any phase, for any reason.

SavingFedAvg is the only strategy class in the project. A plain flwr.server.strategy.FedAvg must never be instantiated directly for the production run.

weighted_average_fit and weighted_average_eval are two distinct functions. No agent may collapse them into one, and no agent may swap which one is assigned to fit_metrics_aggregation_fn vs. evaluate_metrics_aggregation_fn.

Every simulated client evaluates against the identical shared global test split — never a per-client test partition.

federated_global_model.h5 is always built from SavingFedAvg.latest_parameters, converted via parameters_to_ndarrays, loaded into a fresh build_cnn_gru instance. It is never a saved per-client local model.

Production federated runs use num_clients = min_available_clients = min_fit_clients = min_evaluate_clients = 4. Only tests/test_federated_loop.py may use a reduced value (2), and only inside an independently constructed config copy that never mutates configs/config.yaml.

A.6 Evaluation Invariants

Test-set loss is always sourced from model.evaluate(). It is never independently recomputed from predictions.

compute_all_metrics, generate_confusion_matrix, generate_classification_report, generate_class_distribution_plot, generate_training_curves_plot, generate_comparison_table, generate_model_size_comparison, generate_convergence_plot each have exactly one implementation and one owning file, per SDS Section 17. No second implementation of any of these may be created anywhere, including inside dashboard/app.py.

comparison_table.csv always has exactly two rows: Centralized (from centralized_best_model.h5) and Federated (from federated_global_model.h5).

A.7 Dashboard Invariants

dashboard/app.py never trains, never partitions, never runs preprocessing, and never resamples a SHAP background set. It is strictly read-only against outputs/ and data/processed/.

dashboard/app.py may import only: src/utils/*, src/preprocessing/encode_normalize.py::prepare_model_ready_data, src/evaluation/* (metrics/plot loading only), src/explainability/shap_utils.py::explain_single_prediction.

dashboard/app.py must never import src/centralized/, src/federated/, src/partitioning/, or the functions run_preprocessing_pipeline, train_centralized_model, run_federated_simulation, partition_iid, generate_shap_explanations.

Every tab independently guards against missing artifacts via st.error(...) and continues rendering the other tabs — no tab's failure may crash the app shell.

A.8 Artifact Invariants

Every artifact has exactly one producer function and one fixed filename, per SDS Section 9's folder tree. No agent may introduce an alternate filename, an alternate location, or a second producer for an existing artifact.

Overwrite rules are exactly as specified in SDS Section 9's directory table (e.g., processed data and split artifacts are skipped on re-run unless force_reprocess: true; logs are never overwritten, only appended as new timestamped files).

shap_background.npy is written only by generate_shap_explanations and read only by scripts that construct a shap.GradientExplainer from it — never regenerated by a reader.

A.9 Testing Invariants

The 7 test files named in SDS Section 19 are the complete test suite. No agent may rename, merge, split, or add an 8th top-level test file without this contract being amended first.

tests/test_federated_loop.py always constructs its own reduced-scale config; it never reads or mutates configs/config.yaml's production values.

pytest tests/ (the full suite, run together) must exit 0 before any phase downstream of Phase 17 (Blueprint numbering) is considered unblocked.

A.10 Reproducibility Invariants

set_global_seed(config["seed"]) is the first executable statement in every experiments/*.py script, before any data loading, model building, or partitioning.

Every stochastic operation with a seed argument (train_test_split, partition_iid, SHAP background/test sampling) passes config["seed"] explicitly. No stochastic operation anywhere in src/ relies on unseeded global RNG state.

numpy.random.RandomState(seed) is used for both SHAP background and test-sample draws, background first, in that fixed order, on every run.

Determinism claim (as patched by the Blueprint): sklearn/pandas-produced artifacts (scaler.pkl, label_encoder.pkl, categorical_encoder.pkl, train_indices.pkl, test_indices.pkl, class_mapping.json, shap_background.npy) must be byte-identical across runs with an unchanged seed. Keras/TensorFlow-produced artifacts (.h5 models, training-history values) must be numerically identical to 1e-6 tolerance, not bitwise-identical. No agent may weaken either bar, and no agent may claim bitwise-identical Keras outputs as satisfied.

A.11 Configuration Invariants

configs/config.yaml is the single source of every configurable value. No src/, experiments/, or dashboard/ file may define a hyperparameter, path, or magic number inline.

Every key present in config.yaml must be read by at least one function. No agent may add an unused key or leave an existing key permanently unread.

configs/config.yaml itself is modified only by explicit human instruction — never autonomously edited by an agent mid-implementation to "make a phase pass."

PART D — Contract Enforcement Summary

Every phase in Part B is a closed permission set: what is not explicitly listed as allowed is forbidden by default. This applies to CREATE, MODIFY, READ, imports, and configuration keys alike.

"Read only" files may be opened and used but never written to, deleted, or renamed by the phase in question.

"Must never be touched" files are stronger than "read only" — they may not even be opened/read by that phase, because doing so would either violate the Section 11 import graph or represent premature/out-of-order access to an artifact that phase has no legitimate need for yet.

Any function appearing in more than one phase's "MUST be implemented" list is a contract violation and must be resolved by removing the duplicate, not by keeping both.

A phase's Validation Gate failing halts that phase and every phase downstream of it. No phase may be marked complete, and no subsequent phase may begin, until the gate passes.

This contract, once accepted, is binding for the remainder of the project's implementation. Any change to it requires an explicit, human-authorized revision — never an autonomous adjustment by a coding agent mid-task.
